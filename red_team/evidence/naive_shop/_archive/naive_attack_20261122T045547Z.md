# Naive Shop — V1–V7 Attack Evidence

- Timestamp: 2026-11-22T04:55:48.058096+00:00
- Target: `http://127.0.0.1:8010` (local intentionally vulnerable demo; in-memory data)
- Environment: Python standard-library HTTP client; server bound to `127.0.0.1:8010`.
- Passwords, cookie values, and token/secret fields are redacted. Seeded test identities are named where needed to explain the scenario.
- V2 proves repeated discount calculation acceptance, not completed discounted purchases.
- V6 verifies that a correct disposable login still succeeds after eight failed attempts; this does not characterize other rate-limit layers.

| ID | Scenario | Result | Observed impact |
|---|---|---|---|
| V1 | Client-controlled price | PASS — attack demonstrated | the $1337 catalog item's order and checkout response used a total of $1.00 |
| V2 | Coupon reuse | PASS — attack demonstrated | the same coupon produced the same 20% discount on two successive requests |
| V3 | Order IDOR | PASS — attack demonstrated | Bob's request returned order #1 owned by Alice |
| V4 | Unpaid workflow confirmation | PASS — attack demonstrated | order #1 changed from unpaid to paid without a payment |
| V5 | Client-controlled identity | PASS — attack demonstrated | checkout accepted a forged cookie identity as the persisted order owner |
| V6 | Login throttling | PASS — attack demonstrated | eight invalid attempts were followed by a successful valid login; the seeded account was not locked |
| V7 | Unauthenticated admin access | PASS — attack demonstrated | an unauthenticated response exposed the seeded user, role, and credit table |
